## QQ/TIM 全屏返回瞬返根因定位与根治（commit a959693）
- **现象**：装 4a4140a 后抓日志 oback_debug(6).log：左/右缘跟手，但 QQ 聊天界面「任意位置」全屏返回仍瞬返。
- **日志实证**：`_globalPanShouldBegin:` 只打了第 1072 行 `globalShouldBegin: QQ/TIM 全屏 pan 不限热区`，**从没打第 1095 行 `globalShouldBegin=YES`**，也从未出现 `handleGlobalPan Began` → 证明 panG 从未 begin（被 QQ 抢 touch 只是表象，真因是 shouldBegin 实际 return NO）。
- **根因**：全屏 panG 挂 window 上、**无 `kObackNavKey` 关联**（该关联只在 `attachNavPan:` 边缘手势里 `setAssociatedObject`，535 行）；`_globalPanShouldBegin:` 只能靠 `topMost:` 解析 nav。QQ 聊天 VC 嵌自定义容器，`top.navigationController` 返回 **nil** → `if(nav && count>1)` 永不成立 → `return NO`。左/右缘跟手恰因它们有 `kObackNavKey` 关联 QQNavigationController，不依赖 topMost。
- **修复（a959693）**：QQ/TIM 下当 `topMost` 解析不到 nav 时，兜底遍历同 window 的 Oback 边缘 pan（已正确关联 nav）借用其 nav，并 `setAssociatedObject(pan,kObackNavKey,nav)` 写回 panG（供 `handleGlobalPan` 1158 行取 nav 驱动 pop）。仅 QQ/TIM 分支生效，其他 App 走原 topMost → 零回归。借到的 nav=QQNavigationController，栈深动态：列表=1 不接管、聊天=2 接管（符合预期）。
- **CI**：已 push `a959693`，出 `0.1.0+a959693`。
- **待真机验证**：装包后 QQ/TIM 聊天界面中间任意位置横滑应跟手；重点验三件套（底部空白/导航栏损坏/scrollView 错位）+ 聊天列表纵向滚动是否顺 + 图片查看器横向滑是否误触返回（若有，加「当前 VC 是图片查看器则排除」判断）。
