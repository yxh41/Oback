## 滑块数值不更新 + 样式优化 (4288355, 已 push)

**问题**：用户截图显示所有滑块右侧数值卡在 `0.00`，拖动不变化；且字体偏大(15pt)、位置垂直居中偏下。

**根因分析（两条）**：
1. **初始值 0.00**：`willDisplayCell:` 用 `NSUserDefaults floatForKey:` 读值 → PSSliderCell 不像 PSSwitchCell 那样自动将 plist `<default>` 注册到 UD → 首次/升级后读不到 → 返回 0
2. **拖动不更新**：更新依赖 `slider:titleForCurrentValue:` 回调 → 内调 `_obKeyForSlider:` 遍历 `cachedCellForSpecifier:` 反查 key → cell 未缓存时返回 nil → `_obUpdateValueLabelForKey:` 提前 return → 路径断掉

**修复方案**：
- **数据源切换**：初始值 + 实时更新均改为从 `UISlider.value` 直接读取（滑块 UI 位置永远正确）
- **监听方式替换**：删除 `slider:titleForCurrentValue:` 驱动更新的链路，改用 `[slider addTarget:self action:@selector(_obSliderChanged:) forControlEvents:UIControlEventValueChanged]`
- **key 绑定**：`willDisplayCell:` 时用 `objc_setAssociatedObject(slider, "ob_key", key, ...)` 绑定，`_obSliderChanged:` 里 `objc_getAssociatedObject` 直接取，零遍历
- **删除方法**：`_obKeyForSlider:`、`_obTextForKey:value:`、`_obUpdateValueLabelForKey:value:` 均已删除

**样式调整**：
- font: `systemFontOfSize:15 weight:Medium` → `systemFontOfSize:12 weight:Medium`
- label 尺寸: 72×28 → 60×18
- y 定位: `(height-28)*0.5` 居中 → `2` 贴顶
- margin: 动态 accessory 判断 → 固定 16pt
- 格式化字典简化：`@(format, unit)` 二元组 → 纯 `unit` 字符串（格式统一为 >=1 整数/<1 两位小数）

**新增 import**：`<objc/runtime.h>`（关联对象）

## 手势松手必取消回归修复 (73d7a10, 已 push)

**问题**：微信场景右滑/左滑，经常要滑好几下才回到上一页。日志 `oback_debug(8).log` 实证。

**根因**：`handlePan:` 的 switch 把 `UIGestureRecognizerStateEnded` 错误接到
`abortTransition:`（内部**永远调** `interactive cancel`），而含 commit 判定的
`endTransition:` 方法**从未被调用**。每次从边缘滑到松手都走
`beginTransition:pop → abortTransition(state=3=Ended) → cancel` → 返回必被取消；
仅微信自身返回偶尔介入 → 用户感知"滑好几下才回去"。

**修复**：`UIGestureRecognizerStateEnded` 分支改接 `endTransition:`（按 commitRatio/
commitVelocity + 惯性投影正确 `finish` 返回或 `cancel` 不返回）；`Cancelled/Failed`
仍走 `abortTransition:` 紧急清理。

**排查方法论**：日志里 `abortTransition (state=N)` 的 state 值对照
`UIGestureRecognizerState`（Possible=0/Began=1/Changed=2/Ended=3/Cancelled=4/Failed=5）。
state=3 即"正常松手却被取消"，是判定接线错误的强信号。

- **新现象（oback_debug(6).log）**：胶囊不卡屏了，但**界面冻结**——App 界面点不动、只能上滑回桌面；胶囊能正常划出。
- **新根因（冻结，28fc77b 根治）**：`ObackInteractiveTransition` 原是 `NSObject<UIViewControllerInteractiveTransitioning>`，手写 `startInteractiveTransition:` 存 `_ctx` + `finish/cancel` 直接 `[_ctx completeTransition:]`——绕过了 `UIPercentDrivenInteractiveTransition` 的 `finishInteractiveTransition/cancelInteractiveTransition`，导航控制器一直卡在"交互进行中"态 → 界面 userInteraction 失效（上滑是系统手势不受影响）。日志特征：每次 `shouldBegin=YES → beginTransition: pop nav → indicator shown → abortTransition(state=3) → interactive transition cancelled(finished=1)` 连发，且中间无 updateTransition（Began 即调用 popViewControllerAnimated:，手势稍动即取消）。
- **修复(28fc77b)**：① `ObackInteractiveTransition : UIPercentDrivenInteractiveTransition`，`updateWithPercent:`→`updateInteractiveTransition:`、`finish`→`finishInteractiveTransition`、`cancel`→`cancelInteractiveTransition`，删手写 `_ctx/fromView/toView/dimView/startInteractiveTransition:`（视差全交 `ObackAnimator.animateTransition:` 被 scrub）；② pop/dismiss 触发从 `beginTransition`(Began) 移到 `updateTransition` 首次 `p>0.001` 才调用（`triggerTransitionInWindow:`），纯点按/纵向不再启动交互转场。
- 待 CI 出 `0.1.0+28fc77b` 真机验证：界面不再冻结、各 App 边缘内滑返回灵敏、弹窗 dismiss 无黑屏。

- **CI 编译失败(510b361 修复)**：28fc77b 把 pop/dismiss 从 beginTransition 挪到 triggerTransitionInWindow: 后，`triggerTransitionInWindow:` 里残留 `ObackParams *p = [ObackPreferences params];` 未使用 → `-Werror,-Wunused-variable` 编译挂。删掉该行即过。教训：MRC tweak 工程开 `-Werror`，每删一处对变量的引用都要 grep 确认无残留。

- **新 bug（oback_debug(7).log）：左边缘胶囊不出现**。现象：左边缘有震动(haptic)、有效果(系统原生返回跑),但胶囊不出；右边缘正常。日志铁证：整份 `indicator shown` 全 `edge=右`,`edge=左` 一次都没出现（尽管多次 `shouldBegin=YES (左)`）。
- **根因**：iOS `UINavigationController.interactivePopGestureRecognizer` 是左边缘 `UIScreenEdgePanGestureRecognizer`,在左边缘抢赢我们的 pan → 我们的手势永远进不了 Began → 胶囊原只在 Began(`beginTransition:`)显示,故左边缘永不出胶囊；系统原生返回照常跑=用户感知的"效果"。
- **修复(4145117)**：① 胶囊显示从 `beginTransition:`(Began) 提前到 `gestureRecognizerShouldBegin:` 成功路径（与 haptic 同触发点,左右一致,贴合 OPPO"一碰边缘箭头就探出"）；② `showIndicator` 内加 0.4s 安全兜底 `dismissIndicatorSafety`（被抢走/未进入 Began 时自动收起,防残留）；③ `dismissIndicatorSafety` 用 `_indicator.window` 取真实 window 算回弹位置；④ `beginTransition`/`endTransition`/`abortTransition` 均 `cancelPreviousPerformRequests` 取消定时器。

- **UI 需求（db520f6）**：用户要求滑块像截图那样——能看出在调什么参数、当前数值是多少。实现：`ObackSettingsController.m` 重写，在每个 PSSliderCell 右侧挂 UILabel 显示「数值+单位」（如 "40 pt"、"0.32 s"）；通过 `slider:titleForCurrentValue:` 回调实时跟手更新；每个滑块独立格式化(整数/两位小数)与单位后缀；同步修正 Root.plist 中 triggerWidth 默认值 24→40。

## 左边缘一次滑动双返回（微信插件分组）— 诊断 + 修复 (6614322)
- **现象**：微信聊天界面（插件分组）左边缘一次滑动返回两次——先到分组列表、再到微信主界面。
- **根因**：我们的 window 全屏 pan 手势 + 系统原生 `interactivePopGestureRecognizer`(左边缘专属) 抢同一次滑动，各弹一层。Tweak.xm `setDelegate:` 虽然 `interactivePopGestureRecognizer.enabled = NO` 关过一次，但**微信会在自己 view 生命周期里反复把 enabled 重新置 YES**，一次性 disable 不持久 → 原生复活 → 双返回。佐证：右边缘无原生手势、日志里所有右边缘返回都是干净单次；且双返回是微信专属（其他 App 不自己 re-enable）。
- **修复(6614322)**：用 `requireGestureRecognizerToFail:` 让原生手势"失败于"我们的 window pan（成对依赖，App 即便 re-enable enabled，原生 begin 仍须等我们 pan 先失败）——从根上杜绝双触发；同时保留 `enabled=NO` 作第一道防线。三处落地：
  1. `ObackManager.m`：window 挂载 pan 时存 `kPanKey`；新增 `_enumerateNavControllersFrom:block:`(递归收集 VC 树里所有 nav) 与 `_linkNavPopGesturesInWindow:`(对每 nav 设 enabled=NO + requireGestureRecognizerToFail:pan)；`attachToWindow:`(含已挂过的重链)、`windowBecameKey:` 都调用。
  2. `Tweak.xm` `setDelegate:`：在 enabled=NO 后，best-effort 取 nav 所在 window 的 pan 设 requireGestureRecognizerToFail（窗口未知时跳过，仍靠上面两处兜底）。`extern void *kPanKey;`。
- **附带收益**：原生手势成为「我们的手势不可用时」的兜底（shouldBegin=NO 时原生才接管），不丢边缘返回能力。
- **注意/待验证**：日志(11)未抓到双返回现场（微信段进得很晚且多为主界面），属从症状+代码反推，需真机复测确认。若复测仍双返回，则可能是 App 自己的自定义边缘返回（非系统原生），需另寻方案。`requireGestureRecognizerToFail:` 单向依赖，UIKit 在手势 dealloc 时自清依赖，无崩溃风险。
- 推送：`b9bb352..6614322 main -> main`，CI 应出 `0.1.0+6614322`。
