## 冻结复现分析 + 兜底修复 (d4ff196, 已 push)

**用户报告**：华为健康 + 微信"卡界面"（点不动、只能上滑回桌面）。附 `oback_debug(25).log`。

**日志实证关键差异**：
- 华为健康：转场正常走完 → 有 `animator done (cancelled=0)` → 不冻结（该次）。
- 微信：有 `oback-intc finish` + `animator spring applied` 但**无 `animator done`**；且 `interruptibleAnimatorForTransition:` 被**调用两次**（`interruptible ENTER` 出现两次，华为只一次）。

**根因定位**：中断式动画器交互转场里 `completeTransition:` **只**在 `UIViewPropertyAnimator` 的 completion 块调用。`finish` 靠 `continueAnimationWithTimingParameters:` 续跑动画器到底才触发 completion；但该 API 要求动画器处于 Active(paused) 态，微信"动画器被系统二次取用"导致状态错位 → `continueAnimation` **空操作** → 动画器永不到达 Stopped → `completeTransition` 永不调用 → nav 卡交互转场态 → 冻结。这跟 28fc77b 老 freeze（交互状态机没复位，`interacting` 卡 YES）**不是同一类**——`interacting` 每次都正常置 NO，是转场上下文"孤儿化"。

**修复（兜底强制收尾，根绝整类冻结）**：
- `ObackAnimator`：增 `context`(assign) / `completed`(BOOL) 属性 + `forceFinishIfNeeded`；completion 块加 `completed` 守卫防重复 completeTransition。
- `cancel`：在 `pa==nil` 早退**前**先置 `interactiveCancelled=YES`（否则兜底会以"提交"收尾误 pop）；并交 manager 兜底。
- `finish`：日志补 `pa.state` 便于真机定位状态错位。
- `ObackManager`：增 `_watchAnimator`(MRC 强引用) + `_scheduleCompletionWatchdog`：当前 ObackAnimator 0.8s 内若 `completed==NO`，由单例定时器(永不被释放，MRC 安全)强制 `completeTransition`。endTransition 快滑零位移分支仍走系统原生并提前 return（无 ObackAnimator 无需兜底）。

**为什么用单例定时器不是野指针**：manager 单例常驻；`_watchAnimator` 在定时器期间 retain 动画器，回调里 release。`forceFinishIfNeeded` 与动画器自身 completion 靠 `completed` 互斥，绝不重复 completeTransition。

**待真机验证**（`0.1.0+d4ff196`）：① 微信/华为边缘返回后界面不再冻结（最坏情况最多卡 0.8s 强制收尾）；② 留意日志 `oback-intc finish ... state=` 的 state 值——若微信侧 state 仍为 Inactive，即坐实"continueAnimation 空操作"假设，可考虑在 animateTransition 里主动 `pauseAnimation` 进一步根治（当前兜底已足够消除冻结感知）。

## 日志(26)实证：兜底触发了但画面仍卡半屏 + 微信闪退 (d35fce6, 已 push)

**用户报告**：华为健康停在半过渡页面（截图：上一页探出一半、当前页没消失）；微信停同样状态后闪退。附 `oback_debug(26).log`。

**日志铁证（三个独立场景全部复现同一模式）**：

| 场景 | finish 后 | watchdog | 结果 |
|---|---|---|---|
| 华为健康 #1 (line 25-28) | spring applied(state=1) | **forceComplete(cancelled=0) 触发** | 卡半屏！ |
| 华为健康 #2 (line 59-62) | spring applied(state=1) | **forceComplete(cancelled=0) 触发** | 同上 |
| 微信 #1 (line 134-136) | spring applied(state=1) | **无 forceComplete 无 done** | 17s后重启=闪退 |
| 微信 #2 (line 171-173) | spring applied(state=1) | **无 forceComplete 无 done** | 同上 |

**根因深化**：
1. **华为半屏**：watchdog 的 `completeTransition:` **确实被调了**，但 UIKit 只按结果移除/保留 view，**不会把 transform/scale/alpha 从中间值刷到终值** → 视图卡在 fractionComplete≈0.32~0.64 的位置（截图完美印证）。这是上一版兜底的致命遗漏。
2. **微信闪退**：`interruptible ENTER` double-fetch（每次都出现），第二次取回缓存动画器时其态为 Active 但未 pause → `continueAnimationWithTimingParameters:` 在 Active 态下行為异常（可能空操作或触发内部断言）→ 连 watchdog 都救不回来。

**修复三刀（d35fce6）**：
1. **`forceFinishIfNeeded` 归位视图**：调 `completeTransition:` **前**先按 `interactiveCancelled` 把 fromView/toView 全部瞬移到终态（transformIdentity + alpha 归位 + 遮罩清除 + 圆角重置）。提交→fromView 淡出消失+toView 全显；取消→双方复原。**彻底消灭"卡半屏"**。外加 `@try/@catch` 防护 `completeTransition:` 本身断言崩溃（微信闪退的可能原因之一）。
2. **double-fetch pause**：`interruptibleAnimatorForTransition:` 缓存命中时检查 `state==Active` 则主动 `pauseAnimation`，确保返回给系统的是可 scrub 的 Active(paused) 态 → 根除 continueAnimation 空操作。
3. **watchdog 超时 0.8s→0.5s**：更快介入，减少冻结感知时长。

**待真机验证**（`0.1.0+d35fce6`）：① 华为健康不再卡半屏（最坏 0.5s 后瞬移归位）；② 微信不再闪退（@try 防护 + double-fetch pause 根治 continueAnimation 异常）；③ 正常情况下动画器自行完成不受影响（completed 守卫跳过兜底）。

## 日志(28)：彻底弃用 continueAnimation (82e0992, 已 push)

**用户报告**："结果还是一样"——华为健康仍卡半屏、微信仍闪退。附 `oback_debug(28).log`。

**日志铁证（4 个手势，两种结局）**：

| 事件 | App | double-fetch? | forceComplete? | 结果 |
|---|---|---|---|---|
| 1 | 华为健康 | ❌ | ✅ 触发 | 卡半屏（forceComplete 有归位但仍冻结） |
| 2 | 华为健康 | ❌ | ✅ 触发 | 同上 |
| 3 | Solo Letter | ✅ | ❌ 没触发 | 17s 后闪退 |
| 4 | 微信 | ✅ | ❌ 没触发 | 17s 后闪退 |

**根因定论**：`continueAnimationWithTimingParameters:` 在 double-fetch 时会**阻塞主线程**，导致 dispatch_after watchdog（也在主队列）**永远无法触发**。华为单次 fetch 时 watchdog 能触发，但 `completeTransition` 后仍卡半屏——说明中断式动画器状态机与 UIKit 转场系统的交互本身就不可靠。

**修复（彻底换路径）**：
- `forceFinishIfNeeded` 改为：暂停 property animator → 用标准 `UIView animateWithDuration`(0.22s easeOut + BeginFromCurrentState) 把视图从中间态归位到终态 → 在动画 completion 里调 `completeTransition`。这条路径**完全不经过中断式动画器状态机**，不受 double-fetch 影响，不阻塞主线程。
- `finish`/`cancel` 不再调 `applyReleaseVelocity`/`continueAnimation`，直接调 `forceFinishIfNeeded`。
- `_completed` 守卫确保 finish/cancel 先调一次，watchdog 0.5s 后调则直接返回。
- `applyReleaseVelocity` 成为死代码（保留声明不删）。
- watchdog 保留作为最后保险。

**待真机验证**（`0.1.0+82e0992`）：① 华为健康/微信边缘返回后不再冻结/闪退；② 正常返回有 0.22s 平滑归位动画（不再依赖弹簧动量继承）；③ 日志应出现 `animator forceFinish animating` + `animator forceComplete done`。
